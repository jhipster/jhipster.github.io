# Registering a user with additional information

__Tip submitted by [@Paul-Etienne](https://github.com/Paul-Etienne)__

If we need to store more information concerning a user than what JHipster provides by default, the best way is to use
composition: a new entity linked to the built-in `User` entity with a One to One relationship, as described in
[The User entity](/user-entity/#using-composition).

To illustrate this, let's assume we want to store the user's phone number.

## Creating a new entity in a One to One relationship with User

Declare the new entity, let's call it `UserExtra`, and its relationship to `User` in JDL:

```jdl
entity UserExtra {
  phone String
}

relationship OneToOne {
  UserExtra{user(login)} to @Id User with builtInEntity
}
```

The `@Id` annotation on the relationship makes `UserExtra` use the id of its `User`: the generated `UserExtra` class
maps the relationship with `@MapsId`. This way, a `UserExtra` has the same id as its `User`, which makes it easy to load
one from the other.

The relationship is unidirectional, so the built-in `User` entity is not modified.

## Asking for the information at registration

To also ask for the phone number when a user registers, add a field to the registration form of your client, add the
matching attribute to the `ManagedUserVM` class (in `web/rest/vm`), which `AccountResource.registerAccount()` receives,
and save a new `UserExtra` linked to the user created by `UserService.registerUser()`.
